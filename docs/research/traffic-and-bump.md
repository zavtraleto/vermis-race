# Трафик и «bump» (удар без аварии) — OutRun, Slipstream, javascript-racer

Дата: 2026-11-19. Продолжает [slipstream-outrun.md](slipstream-outrun.md) (разделы 4.4, 4.5 — Cannonball) и [javascript-racer.md](javascript-racer.md) (раздел 5). Здесь не повторяется то, что там уже есть; даны ссылки и добавлено новое.

Метки: **[PRIMARY]** — прочитано в исходниках/официальных страницах; **[REVIEW]** — обзоры, форумы; **[INFERENCE]** — мой вывод; **[НЕ НАЙДЕНО]** — данных нет, не выдумываем.

## Вопрос
Как устроены трафик и мягкий удар в OutRun, Slipstream и javascript-racer, и какую минимальную модель трафика + bump взять нам, чтобы игрок мог ловко лавировать в редком трафике, в том числе в дрифте, а контакт давал «bump», а не аварию.

## Короткий ответ
1. Во всех трёх референсах трафик — **попутный** (одно направление), медленнее игрока, плотность низкая. Лобового встречного потока нет (OutRun: [PRIMARY] код — у каждой машины скорость 136..263 при максимуме игрока 294, полосы — две стороны одностороннего шоссе; встречных — нет в коде спавна).
2. Только OutRun-трафик **реагирует** (меняет полосу при помехе); у Jake Gordon быстрая машина сворачивает от игрока/другой машины, медленная не рулит; Slipstream — [НЕ НАЙДЕНО].
3. «Прощающий» удар во всех известных нам реализациях строится на одном: **удар только когда игрок быстрее машины и догнал её**, скорость падает до (чуть ниже) скорости машины, а не до нуля, управление не отнимается (Jake) или отнимается на короткий скид (OutRun: газ = 0, боковой снос ~0.5 с).
4. Для нас рекомендую кандидат **B** (раздел 4): контакт = скорость к скорости машины минус запас, боковой толчок в сторону от машины, короткая блокировка бустов/слипстрима и 0.4 с неуязвимости; дрифт **не срывается**, угол слегка сбивается. Без спина и переворота.

## 1. Как работает трафик

### 1.1 javascript-racer v4 [PRIMARY: `v4.final.html`, перечитано целиком 2026-11-19]
- `totalCars = 200` на трассе длиной `segments.length` (v4 ~ 1600+ сегментов, число не пересчитывалось); спавн в `resetCars()` случайный по всей трассе: `offset = Math.random() * randomChoice([-0.8, 0.8])`, `z = floor(random*segments.length)*segmentLength`, `speed = maxSpeed/4 + random*maxSpeed/(SEMI ? 4 : 2)` (то есть 0.25..0.75 vmax; SEMI 0.25..0.5).
- Спавна/удаления вокруг игрока **нет**: все 200 машин живут всегда, едут по кольцу. `updateCarOffset` у машин дальше `drawDistance` вперёд от игрока отключён («out of sight»).
- Машины **не рулят по кривым** (z только растёт), смена `offset` — по правилу уклонения (формула в javascript-racer.md §5): lookahead 20 сегментов; рулит только быстрая машина, догоняющая медленную (игрока или другую); сила `1/i * (car.speed - other.speed)/maxSpeed` приращения `offset` **за кадр update** (не за секунду). Возврат с края: `±0.1` за кадр при `|offset| > 0.9`.
- Автор сам: в плотном трафике дёргаются влево-вправо; у невидимых AI выключен (проходят сквозь друг друга).
- Хранение: `segment.cars[]` у каждого сегмента (splice/push при смене сегмента); коллизия смотрит только `playerSegment.cars`.

### 1.2 OutRun (Cannonball, [PRIMARY]) — см. slipstream-outrun.md §4.4. Добавлено сегодня
- `otraffic.cpp` (raw GitHub, прочитано через WebFetch-пересказ, цитаты проверены по фрагментам): спавн только если `traffic_count < max_traffic`; гейт `(((spawn_counter - 1) ^ spawn_counter) & BIT_5)`; сторона дороги чередуется `spawn_location & 1` (флаги `TRAFFIC_RHS`, `HFLIP`). Лимит одновременных 2..8 по сложности/этапу (таблица в slipstream-outrun.md).
- Следствие [INFERENCE]: «редкий» трафик OutRun — это 2–5 машин в обозримом пространстве на Easy/Normal. Для 8-полосной дороги нам нужна плотность не в штуках, а в шт./км (см. §4.2).
- Встречного движения нет: машины ездят с положительной скоростью относительно дороги, `z_adjust = (player_speed - traffic_speed) * z` — только догон/отставание [PRIMARY код].
- Трафик в поворотах: отдельной логики нет — позиция машины хранится как (z, x по дороге), а поворот рисуется сдвигом дороги [INFERENCE по структуре `z_adjust` и `hscroll`].

### 1.3 Slipstream [REVIEW/НЕ НАЙДЕНО]
- Плотность, скорости, смена полос — **[НЕ НАЙДЕНО]** (devlog'ов нет, см. slipstream-outrun.md §7).
- Из обзоров: трафик «слишком медленный после дрифта» (жалоба), холмы/впадины скрывают трафик, трафик можно отключить в Cannonball-режиме, слипстрим берётся за трафиком и соперниками, столкновение = потеря скорости и времени. Traxion (https://traxion.gg/slipstream-switch-review-a-nostalgia-fueled-road-trip/): после набора слипстрима новый не нужен, пока не врежешься и не потеряешь инерцию [REVIEW, пересказ поиска, страница целиком не читалась].
- Конкретную механику удара (спин, время) прочитать в первичных источниках не удалось.

### 1.4 Другие
Early NFS / Road Rash / Horizon Chase: **не исследовалось**, фактов нет. Поиск по NFS-трафику выдал только форумы про современный NFS (нерелевантно). Не использовать как основу.

## 2. «Bump»: что происходит при ударе

| | Скорость игрока | Боковая позиция | Управление | Машина-цель | Длительность | Спин/авария |
|---|---|---|---|---|---|---|
| javascript-racer [PRIMARY] | `speed = car.speed * (car.speed/speed)`: на vmax при car.speed=0.5 vmax → 0.25 vmax (чем быстрее игрок, тем сильнее падает; формула квадратично усиливает разницу) | не меняется | **не отнимается**, мгновенно | не меняется (едет дальше) | один кадр; повтор на следующем кадре, пока перекрытие | нет |
| | `position = car.z - playerZ` — игрок **телепортируется** позади бампера | | | | | |
| OutRun (Cannonball) [PRIMARY] | `max(traffic_speed - 80, 0)`; газ = 0 во время skid/spin | `skid_counter += ±20` (знак по стороне машины), предел ±30; снос `SKID_X_ADJ = 24` за тик, пока счётчик не обнулится | отнято на время скида | скорость traffic −80 (floor 0) — машина тоже замедляется | скид ≈ десятки тиков (30 Гц) [INFERENCE] | спин только если `|skid|>6` и `(rand & collision_mask)==collision_mask`; при быстрых скоростях (≥200 из 294) — переворот |
| Slipstream [REVIEW] | «большая потеря скорости» | [НЕ НАЙДЕНО] | [НЕ НАЙДЕНО] | [НЕ НАЙДЕНО] | [НЕ НАЙДЕНО] | «деревья/знаки переворачивают вперёд»; соперник может сбить лёгким ударом — машина крутится (обзоры) |

Задний удар vs боковой:
- javascript-racer [PRIMARY]: условие `speed > car.speed` и `overlap` по x с percent 0.8 (хитбокс 80% ширины) — это **только догон сзади**. Если игрок медленнее машины, «удара» нет вообще. Боковой контакт отдельно не обрабатывается: если у обгоняющего игрока перекрытие по x есть в том же сегменте, игрок получает ту же «останову» — боковой скользящий удар = задний.
- OutRun [PRIMARY]: `check_collision` требует `z>>16 >= 0x1D8` (машина на уровне игрока) и перекрытие по x (`x1<0 && x2>0`, ширина w = 11/16 спрайта, т.е. хитбокс уже спрайта). Знак бокового толчка определяется стороной, где трафик (`sprite->x < 0 ? -RESET : RESET`). Отдельного режима для заднего/бокового нет, разница только в величине перекрытия по x [INFERENCE].
- Cannonball «bumper enhancement» (`d0 /= 3`) — порт ослабляет скид втрое; настройка есть в CannonBall DX (kickoff-brief.md). Это прямое свидетельство, что оригинальный удар воспринимается как слишком жёсткий и поддаётся смягчению [PRIMARY код + INFERENCE о причине].

Что делает удар прощающим (общее из кода) [INFERENCE по формулам выше]:
1. Хитбокс уже визуального спрайта (0.8 у Jake, 11/16 у OutRun) — «царапины» не считаются.
2. Скорость падает **до скорости цели**, не до нуля: игрок остаётся «в потоке», может объехать.
3. Нет мгновенного спина на низких скоростях (OutRun: `<100` — просто отскок).
4. Нет жёсткого запрета ввода (Jake) или короткий (OutRun).

## 3. Детекция столкновений в псевдо-3D

- **Перекрытие в (z, x).** По x — интервальный тест с ширинами (`Util.overlap`, javascript-racer.md §5: `!(max1 < min2 || min1 > max2)`). По z — у Jake «один сегмент» (200 ед.), у OutRun порог по z (`0x1D8`). Для нас: длина машины как параметр `carLength` (в сегментах), перекрытие по z: `|zA - zB| < (lenA + lenB)/2`.
- **Списки по сегментам** (Jake): `segment.cars[]`, переносить при смене. Для нас при ≤ ~30 живых машин проще **линейный перебор** по плоскому массиву `cars` в фиксированном порядке индексов — нулевые аллокации, детерминизм, без индексов-списков [INFERENCE].
- **Туннелирование.** Jake сознательно ограничил `maxSpeed = segmentLength/step` («не больше сегмента за кадр → проще коллизии») [PRIMARY]. У нас: `vmax` = 60 сегм/с, шаг 1/120 → **0.5 сегмента за тик** собственного пути; относительная скорость с попутной машиной не больше этого. Если `carLength ≥ 0.5` сегмента, пропустить машину нельзя. Рекомендация [INFERENCE]: всё равно использовать **свипнутый тест по z**: `zPrev` и `zNow` игрока относительно машины пересекают интервал перекрытия (одно сравнение) — тогда безопасно при любых `vmax`/`DT` изменениях.
- Жёсткий порядок шага: движение трафика → движение игрока → тест коллизий → применение bump; всё внутри одного `step`, события — в `SimEvent` буфер (рендер: тряска, звук).

## 4. Предложение для Vermis Race

### 4.1 Минимальная модель
- Трафик — `Car` с `kind: 'traffic'` в том же `cars[]`; проходит через тот же `step`; ИИ только создаёт `InputFrame` (sim.md). Начальное поведение: `steer = 0`, `brake = false`, `drift = false`; скорость — своя цель `trafficSpeed` (доля `vmax`), через параметр `CarParams` трафика (`vmax = trafficSpeed`, `accel` большое), чтобы `speed` просто держалась. Это без новых правил движения.
- Полосы: 8 полос, ширина полосы в x = `2/8 = 0.25` полуширин (R22c). Спавн по центру полосы: `x = -1 + (lane + 0.5) * 0.25`.
- Детерминированный спавн: из `state.rng` (seeded). Пул фиксирован `trafficMax`; свободная машина **переспавнивается впереди** игрока на `trafficSpawnAhead` сегментов (за пределами видимости, за туманом), если плотность ниже целевой; уезжает назад — когда `z < playerZ - trafficDespawnBehind`. Плотность задаётся как `trafficPerKm` (машин на 1000 сегментов) → выбирает интервал между спавнами; один `rng` вызов на спавн (полоса), один на скорость. Порядок вызовов фиксирован по индексу слота.
- Скорости: диапазон `trafficSpeedMin..trafficSpeedMax` (доли vmax) — ниже игрока всегда, иначе слипстрим H5 теряет смысл. Ориентир из OutRun: 136..263 при 294 → 0.46..0.89 vmax [PRIMARY число, мой пересчёт]; Jake: 0.25..0.75 [PRIMARY]. Стартовые числа предлагаю в середине: 0.35..0.7 [старт].
- Смена полос трафиком: **в v0 нет**. Причина: ловкое лавирование — навык игрока; у Jake и OutRun уклонение трафика — источник «дёрганья» и непредсказуемости (Jake в статье сам назвал дёрганье проблемой; OutRun — самая сложная часть кода). Опция на потом: `trafficLaneChange` (флаг) — 1 смена полосы на машину, только с телеграфом (мигание, 1 с).
- Повороты: трафик едет вдоль дороги в своих `x` (дорога задаёт форму, как у Jake `z` только растёт). Машины не должны спавниться на выходе из `hard`-поворота или в 2 с перед ним (пиллар «Speed without chaos»): правило запрета спавна для сегментов с `|curve| > trafficSpawnMaxCurve` в окне `trafficSpawnAhead`. Без запрета при невидимости за поворотом игрок не успеет увидеть [INFERENCE].
- Размер хитбокса: `trafficHitW` в полуширинах (старт 0.08, т.е. узко: 2 полосы = 0.5), `carHitW` игрока в дрифте меньше визуальной ширины (`angle` увеличивает визуальную длину, но хитбокс — только по `x`, см. ниже).

### 4.2 Плотность «редкого» трафика
Старт: 1 машина на 120 сегментов дороги в области видимости (≈ 2 секунды до встречи на vmax, когда ты «ловишь» машину) → при `drawDistance` ~150–200 сегм. это 1–2 машины на экране одновременно. Значение — гипотеза для плейтеста, не измерение. [INFERENCE: сопоставил с OutRun Easy 2..3 в зоне видимости.]

### 4.3 Кандидаты правил bump (черновики; ID временные, R40+ зарезервированы под коллизии)
Общие определения (для всех кандидатов): `hit` = в тике выполнено перекрытие (z свипнутый, x интервальный по `carHitW`, `trafficHitW`) **и** `speed > traffic.speed` (догон; обгон с боком тоже догон по определению) **и** `bumpIframes == 0`. Параметры — в `src/data`, числа ниже — стартовые обозначения, не измерения.

**Кандидат A — «как Jake»: прямолинейный.**
- R40A. При `hit`: `speed = traffic.speed * (traffic.speed / speed)` (формула Jake) и `z` игрока откатывается к `traffic.z - carLength`. Состояние `GRIP/DRIFT` не меняется, `vx` не трогаем.
- Плюс: простая, ноль состояния. Минус: телепорт по z (рендер дёргает камеру; при 120 Гц шаге и дрифте заметно); в дрифте игрок «упирается» в машину и тут же получает повторный hit, пока не уйдёт вбок, — без iframes серия ударов; бокового «bump» нет, нет ощущения толчка.

**Кандидат B — «bump»: скорость к цели + боковой толчок + iframes (рекомендую).**
- R40. `hit` → `speed = max(traffic.speed - bumpSpeedLoss*vmax, 0)`; ограничитель: не ниже `bumpFloor * vmax` — не даёт встать.
- R41. Боковой толчок: `vx += bumpKick * sign(x - traffic.x)` (знак: от машины; при равенстве — от центра дороги), `vx` ограничить `bumpKickMax`. Это работает и через R12 в GRIP, и в DRIFT (R12 с `gripDrift` догонит цель — толчок сам рассосётся). Сдвиг `x` напрямую не применять (чтобы не телепортировать и не ломать R18).
- R42. Бесчувствие к повторным ударам: `bumpIframes = bumpInvulnTime` (сек, тики); пока >0 удар не срабатывает и **та же машина** не может ударить повторно (`bumpLastId`). Рендер мигает моделью.
- R43. Дрифт: состояние **не срывается** (R21 не вызывается); `angle -= dir * bumpAngleKick` (угол слегка сбит — всегда в сторону уменьшения, нижняя граница 0 → дальнейшая жизнь в дрифте решается обычными R21); `lowTicks` не трогаем. Причина: пиллар 3 («эффектно в дрифте, без торможения») — удар не должен ломать то, что игрок строит; удар даёт цену скорости (`bumpSpeedLoss`) и слегка сбитый угол, но не «спин».
- R44. Слипстрим H5: удар обнуляет `draft` (`draft = 0`) и блокирует заряд на `bumpDraftLockTime` секунд (как в Slipstream: ошибка = потеря потока [REVIEW]).
- R45. Рулевой ввод не блокируется (в отличие от OutRun) — управление отнимать на touch неприемлемо: палец ведёт, а машина «отпускает» [INFERENCE].
- Плюс: ощутимый, но прощающий; повторные удары невозможны; не срывает дрифт. Минус: больше параметров (6).

**Кандидат C — «скид по OutRun» (облегчённый).**
- Как B, но вместо `vx`-толчка — счётчик `skidTicks` (как `skid_counter` ±20, снос по x за тик), газ = 0 на `skidTicks`, при `speed > bumpSpinSpeed*vmax` и `rng` — спин. Это ближе к OutRun [PRIMARY], но (1) нужно новое состояние в Car, (2) спин требует нового визуального состояния (рендер R24-подобный), (3) отнимает газ — противоречит «автогаз» (R14), (4) в дрифте непонятно, что делать с `dir`/`angle` при спине.
- Рекомендовать **не стоит** для v0: больше всего вопросов к автору (аварии в пилларах нет).

### 4.4 Рекомендация
**Кандидат B**, потому что: (1) использует уже существующие механизмы (`vx` через R12, скорость через R14 до нового потолка), никакого нового состояния кроме двух счётчиков (`bumpIframes`, `bumpDraftLock`) и `bumpLastId`; (2) в дрифте сохраняет состояние — пиллар 3; (3) защита от повторных ударов; (4) не отнимает ввод. Идея ослабления до «bump» подтверждена фактом: порт Cannonball добавил «bumper enhancement» с делением скида на 3 [PRIMARY] — значит, оригинальный жёсткий удар считают лишним.

Стартовые имена параметров (значения подберёт implementer/bot, не мы): `bumpSpeedLoss`, `bumpFloor`, `bumpKick`, `bumpKickMax`, `bumpInvulnTime`, `bumpAngleKick`, `bumpDraftLockTime`, `carLength`, `carHitW`, `trafficHitW`.

### 4.5 «Near miss»
Идея автора/Slipstream: проезд впритык = бонус (заряд слипстрима быстрее). Минимальная форма [INFERENCE, [гипотеза], флаг]: в тике, когда игрок проезжает уровень по z машины (свип), если `0 < |x - traffic.x| - (carHitW+trafficHitW)/2 < nearMissGap` и удара не было, добавить `draft += nearMissDraftGain` (≤ 1). Метрика: число near miss за круг. Риск: игрок сознательно «трётся» о трафик — на это отвечает общий лимит заряда и отсутствие скорости как награды в v0.
Слипстрим за трафиком [решено H5]: полоса `draft` как в brief; удар обнуляет (R44). Конфликт: слипстрим требует ехать **за** машиной в той же полосе — то есть **на грани** удара; хитбокс по `carHitW` меньше визуального, а iframes не должны давать «бесплатный» слипстрим: во время `bumpIframes` `draft` не растёт.

### 4.6 Метрика для бота/гейта: «редкий трафик проходим, и в дрифте»
Тестовая трасса `traffic` (детерминированный seed), три уровня бота (как сейчас в `bots.json`). Метрики за круг:
1. `bumpsPerLap` у бота «ровный» (держит полосу без лавирования, дрифтует по трассе) — нижняя граница ожидаемого числа ударов при плотности `trafficPerKm`: должно быть ≥ 1 (трафик реально мешает) и ≤ N_max.
2. Бот «лавирующий» (смотрит на машины в окне `lookaheadSeg`, выбирает свободную полосу, смещаясь в пределах `steerRate`, в том числе в дрифте через `angle`): `bumpsPerLap = 0` в ≥ 90% seed'ов — иначе трафик непроходим, а значит нечестен.
3. Потеря времени: `lapTime(traffic) / lapTime(no traffic) ≤ 1.08` для лавирующего бота; ≥ 1.2 для «ровного» — разница доказывает, что навык (лавирование) окупается.
4. Подмножество «в дрифте»: доля тиков в DRIFT на отрезке 2 с перед машиной ≥ 0.5 и при этом `bumps = 0` — доказывает, что дрифтуя, можно уворачиваться (`angle` управляется как руль).
5. Ширина просвета: для каждой машины `gapLanes` (число свободных полос на её z) ≥ 1; гейт на уровне генерации спавна.
Все пороги — `gate.config.json` (задаёт автор). Красный гейт = находка, не повод подкручивать.
