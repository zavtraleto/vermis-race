# Спайк: полоса пальца в дрифте (D1) и дрифт «не в ту сторону»

Дата: 2026-11-19. Ветка `feat/rivals`. Скрипт: `tools/spike/driftband.ts`. Повод — отзыв автора: «в дрифте ВЛЕВО легко проезжаю ПРАВЫЕ повороты, так быть не должно». Причина и варианты — [drift-systems.md](drift-systems.md) §3–§5. Здесь — числа.

Повторить:
```

node tools/run-ts.mjs tools/spike/driftband.ts --only "V0;H uMin 0 wp" --set driftLat=0.5   # выборка вариантов, свои числа машины
```
Прогон ~1 мин. `src/`, тесты и данные не тронуты.

**Как устроено.** Шаг модели B одной машины (R80–R88 без слипстрима, столбов и трафика) скопирован в скрипт, чтобы подменять ветку DRIFT. Копия V0 сверяется с **настоящим** `step` при каждом запуске (смешанный ввод: рывок, удержание, руль против, отпускание, повторный рывок, на прямой, `medium`, `hard`, `−hard`): расхождение `x`, `vel`, `speed` = **0.00e+0**. GRIP, R81, R82, R82b, R85, R86 во всех вариантах — сегодняшние. Данные — настоящие (`src/data/cars/base.json`), стены и потеря на обочине выключены (`xLimit` 1e9, `offroadMul` 1), столбы R47 выключены. Скорость старта `vmax`, дальше свободная (R86), кроме окон R89b, которые тесты меряют на закреплённой `vmax` (так же и здесь). Полоса = 0.25 полуширины (пш). «Палец» `u` — сырой руль × `dir` в [−1, 1].

**Варианты.**
- **V0** — сегодня: `slipT = dir*slipFull*clamp(u,0,1)`, `velT = dir*driftLat*(slip*dir/slipFull + min(0,u)) − driftPush*A`, опережение `e = clamp(u,0,1) − slip*dir/slipFull`.
- **V1 (D1)** — палец на всю ось → дуга только своей стороны: `uEff = uMin + (1−uMin)*(u+1)/2`; `slipT = dir*slipFull*uEff`; `velT = dir*driftLat*slip*dir/slipFull − driftPush*A`; `e = uEff − slip*dir/slipFull`. `uMin` ∈ {0.2, 0.3, 0.4}.
- **V2** — V1 + снос «против дрифта»: если `A*dir < 0`, вместо `driftPush*A` берётся `wrongPush*A`. `wrongPush` подобран так, чтобы дрифт не в ту сторону уходил с дороги в `medium` и `hard` за то же время, что GRIP с рулём 0 (табл. 0).
- **V3** — V2 + автовыход (как R82), если `A*dir < 0` держится дольше `T` = 0.3 с.
- **H (вне задания, добавил сам)** — «половина оси»: `uEff = uMin + (1−uMin)*clamp(u,0,1)`, палец против `dir` = палец 0; остальное как V2 (тот же `wrongPush`), с автовыходом и без. При `uMin = 0` это ровно «убрать член `min(0,u)` из R84 + снос против дрифта». Добавил, потому что V1 сдвигает все удержания и окна R89b (ниже), а H лечит жалобу и не трогает правильную сторону.

Знаки в замерах: дрифт всегда `dir = +1` (вправо); «не та сторона» — левый поворот (`curve = −C`, `A*dir < 0`), наружу = +x. Это зеркало «левый дрифт в правом повороте» из жалобы.

Шум V0 0.045 — худший из 5 зёрен (тест берёт 3 зерна; в задании «сегодня 0.024–0.042»). Вход и выход у всех вариантов одинаковы: на правильной стороне формула входа не меняется.

**S-поворот** (фигура `scurve`: `hard` вправо 120 сег., выход 15, вход 15, `hard` влево). Старт — установившийся правый дрифт на осевой. В дрифте палец ведёт регулятор `u = u_уд + (1.5*(d*0.2 − x)*d − 0.6*vx*d)/S` с удержанием и наклоном *своего* варианта (так игрок «одинаково хорошо» владеет каждым). В момент `tr` (с от точки, где кривизна проходит 0) — отпустить (руль к 0 за 100 мс), 0.1 с без пальца, касание в 0, рывок к −1 за 60 мс, дальше регулятор. Потеря — отставание от машины, которая всё время едет на `vmax` (одна мерка для всех; она включает и честную цену дрифта, поэтому смотреть на разницу). «Окно» — все `tr`, при которых машина остаётся на дороге и заканчивает в левом дрифте; перебор `tr` от −1.2 до +0.8 с.
- При `tr = 0` все варианты одинаковы (0.25 пш, 0.407 с): регулятор, нормированный на свой наклон, компенсирует переотображение.
- **V0 и V1 пускают перекладку на 1.2 с (и больше — край перебора) раньше**: рывок влево ещё в правой дуге, и машина проходит конец правого поворота в левом дрифте — та самая жалоба, видна и здесь.
- V2/H: окно −0.85…+0.6 с (≈ 1.45 с) — перекладка остаётся простой; самые ранние перекладки вылезают к краю (max|x| ≈ 1.0) и выигрывают 0.05–0.07 с у `tr = 0` — «hard to master»: рискнуть ранней перекладкой.
- V3: окно сзади расширяется до +0.8 с (автовыход сам закрывает старый дрифт), но в лучшем случае автовыход срабатывает 1–2 раза: ранний рывок в новую сторону, пока дорога ещё поворачивает по-старому, гасится автовыходом через 0.3 с. Это скрытая ловушка для игрока.

## 7. Бот модели B (`src/bot/driver.ts`, только рассуждение)

Закон бота в дрифте: `steer = bDriftCurveGain*cAhead*sp + bDriftSteerGain*(xTarget − x) − bDriftSteerDamp*vx`, сырой руль; при повороте в другую сторону впереди (`c*dir < 0` в пределах `bReleaseLook`) бот отпускает дрифт.
- **H uMin 0**: в рабочей зоне (`u ≥ 0`) ничего не меняется — удержания, наклон, усиления те же. Отрицательный руль теперь насыщается на «пальце 0» (наружу только `−driftPush*A`): бот с линией `bDriftLineX` и демпфированием иногда давал руль < 0 для коррекции наружу — она станет слабее (0.40 с на полосу вместо 0.26). Главный риск — **отпускание**: если `bReleaseLook` короче, чем бот держит дрифт в начало обратного поворота, `wrongPush` 0.13 вынесет его за ~0.7 с в `hard`. Проверка — `npm run bot && npm run gate` (на `drift-run` и `test-twisty` с `scurve`/`chicane`/`flick`).
- **V1/V2**: закон формально переносится (отображение линейно и монотонно), но всё сдвигается: удержание `hard` 0.82 → 0.48, `medium` 0.54 → −0.32, наклон ×0.35. Обратная связь станет в ~3 раза мягче, а член кривизны даст неверное смещение — нужно переподобрать все три усиления дрифта для трёх уровней (`src/data/bots.json`) и заново пройти гейт.
- **V3**: бот, отпускающий поздно, будет выкидываться автовыходом в GRIP посреди поворота — новый режим, который бот не планирует.

## 8. Рекомендация

**H uMin 0 + `wrongPush` 0.13 без автовыхода** (то есть: убрать член `min(0, u)` из R84 и опережение против `dir` — оно и так 0; в повороте против `dir` снос считать с `wrongPush` вместо `driftPush`). Стартовые числа: `wrongPush` 0.13 (подбор 0.12–0.14; 0 = выключено, флаг-гипотеза), `uMin` 0 (вариант H uMin 0.2 — запасной, если автор захочет «дрифт на прямой всегда чуть едет вбок»). D1 из [drift-systems.md](drift-systems.md) §5.1 в чистом виде (V1/V2) **не рекомендую**.

Почему не D1. Жалобу V2 лечит так же, как H (1.02–1.04 / 0.72–0.75 с), но ценой почти всех окон правильной стороны: палец в центре на прямой уводит дрифт на 0.28–0.32 пш/с (окно 0.05), докат после возврата пальца 0.9–1.06 (окно 0.06), `medium` держится пальцем *против* дрифта, наклон 0.14–0.18 (окно 0.4–0.8), уклонение `h−0.5` 2.4 с / никогда (окно 1.0), близость к A 0.24–0.26 (окно 0.15), полоса навыка в `hard` расширяется в 2.5–3.4 раза — мастерства меньше. Плюс у V1 один — шум 0.016 против 0.045.

Почему не V3. Автовыход превращает ошибку «не та сторона» в `easy`/`medium` в бесплатную (дорога держится в GRIP с полным рулём), а в S-повороте гасит слишком ранний рывок — магия, которую игрок не видит.

**Что станет хуже с H (говорю прямо):**
- Уклонение в дрифте **против `dir`** на прямой исчезает: было 0.67 с на полосу, стало «никогда» (на прямой дрифт едет только в свою сторону или прямо). Ранняя просьба автора «поворотливость в дрифте» — в эту сторону теряется.
- Уклонение **наружу** в установившемся `hard` полным пальцем против: 0.26 → 0.40 с на полосу. Наружу пальцем «удержание − 0.5»: 0.81 → 0.81 (без изменений).
- Дрифт не в ту сторону **совсем без угла** (палец против → `slip` 0): кузов прямо, а машину сносит наружу. Это честно, но выглядит как «GRIP без руля»; если автору не понравится — H uMin 0.2 (угол не ниже 20% от полного, на прямой 0.09 пш/с вбок).
- Перекладка в S: окно рывка −0.85…+0.6 с вместо «когда угодно» (сегодня ≥ −1.2…+0.8).

**Окна R89b при H uMin 0** — все остаются, ни одно число не двигается (hard 0.402 / 0.058 / 0.460 / 0.816 / 36.6° / 0.935; medium 0.258 / 0.202 / 0.537 / 24.1° / 0.957; прямая 0.46 / 0.000; вход 0.020 / 0.43 / 0%; выход −0.443; шум 0.045; рывок 0.35 / докат 0.000; близость A 0.134; `hard h−0.5` 0.81). Меняется только **текст** R84 («руль против `dir` после нулевого угла ведёт машину наружу с той же властью `driftLat`» → убрать) и правило-тесты формулы R84 (`tests/sim/modelb_rules.test.ts`: «R84 DRIFT counter-steer term: min(0, u) moves the car against dir with driftLat» и формула velT) — это изменение правила, сначала brief, решение автора. Новое окно предлагаю назвать заранее: «дрифт против изгиба (палец до упора против) уходит с дороги в `medium` и `hard` не позже, чем GRIP с рулём 0 + 10% (сейчас 1.06 / 0.71 с), в `easy` — наружу ≥ 0.3 пш/с».

Для H uMin 0.2 (если выберут): окна сдвигаются — `hard` u=0 0.402 → 0.310, наклон 0.460 → 0.368 (в окне), удержание `hard` 0.816 → 0.771 (в окне), `medium` u=0 наружу 0.258 → 0.166 (**вне** 0.2–0.35), удержание `medium` 0.537 → 0.422 (**вне** 0.45–0.55), прямая u=0 0.000 → 0.092 (**вне** ≤ 0.05), докат 0.000 → 0.247 (**вне** ≤ 0.06), близость A 0.134 → 0.170 (**вне** ≤ 0.15), `h−0.5` 0.81 → 1.08 (**вне** ≤ 1.0).

## 9. Что не проверено
- Только одна машина на постоянной/кусочной кривизне; бот, трафик, соперники, стены и обочина не гонялись. Гейт (`bot` + `gate`) после правки обязателен.
- «Полоса навыка» — моё определение (3.5 с, ±0.6 пш от осевой); на другой длине дуги ширина другая, но порядок (V1 в 2.5–3 раза шире) не меняется.
- S-поворот — один регулятор на все варианты, нормированный на свой наклон; живой палец ведёт себя иначе. Потеря времени меряется против машины на `vmax`, разница между вариантами ≤ 0.07 с.
- Ощущение на телефоне (кузов без угла при «не той» стороне, потеря уклонения против `dir`) — оценивает автор.
