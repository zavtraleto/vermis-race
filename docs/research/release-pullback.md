## Предложения и прогноз (тем же спайком)

> 2026-11-21: F3 (экспонента с обрезкой руля) заменён «разгоном сноса» R85f, F4 не взят; принятые правила — R84c, R85e, R85f, R27d, R89d в brief; числа — раздел «Второй замер» ниже.

**F1 — R85b: опережение только «ловит».** Опережение GRIP (R85b + R85c) в сторону пальца (`lead·steer > 0`) — как сейчас; иначе оно может только погасить боковое движение курса, но не толкать дальше: `vx` остаётся между 0 и `vel·sp·latScale`. Новых чисел нет. Прямая: **без изменений** (довыкат, остановка R89c, смена полосы — те же числа, опережение на входе и «ловит» на отпускании сохраняются). Поворот: бросок в первом тике убран (`vx` 0 → 0.00 вместо −0.91/−1.41), установившиеся режимы R89b не меняются (там опережение = 0).

**F3 — новое правило «память отпускания» (сим).** После отпускания (сырой руль стал ровно 0 из ≠ 0, или выход из дрифта R82) и пока руль 0, курс GRIP считается с рулём `sRoad·exp(−t/relTau)`, где `sRoad = clamp((A + yawAlign·sG)/(yawRateMax·f), −1, 1)` — руль, при котором `vStar = 0` на этом повороте (машина держит линию). На прямой `sRoad` = 0 — ничего не меняется. Любое касание сбрасывает память. Параметр `relTau` (старт 0.4 с), флаг гипотезы. Нужно поле состояния (тики с отпускания) в `Car`.

**F2 — рендер: медленный возврат камеры + односторонний «подхват».** Смещение `o = x − camPosX` идёт к `clamp(vx·camLagTau, ±camLagMax)`: с `camLagTau` 0.08, пока растёт, и с `camReturnTau` 0.4 с на возврате. В R89 член `leadDeg·lead` — только когда `lead·vx > 0`.

**F4 — альтернатива F2: камера без отставания с долей.** `camPosX = (1 − camFollowK)·x`, `camFollowK` 0.2: машина на экране стоит там, где она на дороге, и никогда не возвращается (полоса = 27 px, край дороги = 108 px от центра). Заменяет R27b.

За 0.6 с — 0.125 / 0.112 (ориентир 0.10), за 1.5 с — 0.44 / 0.39 (ориентир 0.30). Уложиться можно только если отпускание держит лучше полного руля. Не предлагаю.

### «Рельсы» (S6–S8), F1 + F3-старое, установившийся дрифт к `dir` 3 с

Дрейф `x` к стороне дрифта за 1 с на пальце в полу (руль 0 и 0.5 — одна точка из-за пола R83b `driftMinU` 0.5) / на полном руле:

Неожиданное:
1. «Просто снять долю выноса» (naive) с полом R83b при 1 превращает любой поворот в прямую: палец в центре уводит внутрь на 0.23 полуш./с. Поэтому R84c снимает только ту часть выноса, что сильнее увода пола (`max(0, driftPush·A·dir − driftLat·driftMinU)`). Тогда при 1 палец на полу ведёт ровно по дуге, а `easy` и прямая не меняются вовсе.
2. Пальцем линию можно сделать только уже (внутрь). Шире — никак: руль от −1 до 0.5 упирается в пол, наружу только отпусканием. Угол кузова на полу остаётся 22–23° в любом повороте и не растёт с крутизной, как в Ridge Racer.
3. «Рельсы» не трогают отпускание (за него отвечает R85f), прямую (0.230 / 0.460 при любом `driftRail`) и дрифт против поворота (уход с дороги 0.958 / 0.625 / 0.483 с без изменений).
4. Объединить «рельсы» с памятью R85f одной величиной нельзя. Обе — «руль, держащий линию», но в разных моделях: в DRIFT это доля угла `h = driftPush·A·dir/driftLat` (как в R83c), в GRIP — `Y = A + yawAlign·(vT + sG)`. Это две формулы одного смысла.
