# Спайк «печать» (`?print=1`, `?print=2`) — одноразовый

Что сделано: обычный псевдо-3D кадр рисуется в `WebGLRenderTarget` 360×640 (nearest, RGBA, очистка альфой 0 = «ничего не нарисовано» = небо), затем один полноэкранный квад `ShaderMaterial` (`src/render/printPass.ts`) печатает его на холст 360×640 × `scale` (по умолчанию 1080×1920, CSS не меняется). `src/data/print.json`: 16 цветов, общие числа `params`, пресеты `presets` (небо, цвета заглушек, тени тел). `?print=<имя пресета>`; есть «1» (Сад, сиреневое небо, жёлтое солнце) и «2» (киноварь → жёлтый, чёрное солнце, пурпурная обочина). Без флага кадр попиксельно прежний (10 эталонов `npm run shot` совпадают побайтно).

Порядок в шейдере: поле бумаги с рваным краем → контур (key) по разнице соседних пикселей исходника (граница рисунок/небо — всегда) + штриховка тёмного → иначе небо (полосатая растяжка до горизонта камеры растром + плоское солнце) или цветная форма со сдвигом приводки: двухтоновое тело (пара цвет→тень) или два ближайших цвета палитры, выбор по порогу растра → «сухая краска» на тёмных заливках → точки дымки цвета горизонта → пропуски бумаги.

- Цвет: при печати выключен `THREE.ColorManagement`, всё — сырые sRGB-байты. Проверка чтением пикселей: каждый кадр ≤ 16 цветов, все ровно из палитры.
- Тела машин: при печати цвет кузова = цвет → тень на (1 − освещённость грани) × `amount` (игрок — в геометрии, трафик — через `#define PRINT_DUO` в шейдере трафика). Шейдер печати знает эти пары и квантует вдоль них, а не по двум ближайшим (иначе кость уходит в бумагу/голубой). Стекло, фары, колёса — плоские.
- Дымка и небо считают горизонт из `camera.horizon` и поворачиваются вместе с креном R27 (холмы не учитываются).
- Растр AM — точка по площади (тон t ≈ доля закрытой ячейки).

## Слайдеры (группа «Печать»)
Тип растра (0 точки / 1 стохастика / 2 Байер), шаг и угол растра, зерно стохастики; сдвиг цвета X/Y; порог и толщина контура (1–2 пикселя игры); штриховка (шаг, порог); сухая краска; дымка (высота полосы, сила); пропуски (равномерные, в пятнах, порог пятен, у края); поле бумаги и рваность края; солнце (радиус, высота); масштаб печати. Только в JSON: палитра, роли, пресеты, зерно/период сухой краски и пропусков, `amount` теней.

## Замеры (2026-11-19, `node tools/spike/print-shots.mjs --gpu`, AMD Radeon встроенная, D3D11, headless)
- Живой цикл: p50 16.7 / p99 16.8 мс с печатью и без (упор в vsync); draw calls 4 против 3.
- Без vsync (рендер + readPixels, сцена traffic): 2.9 мс с печатью против 0.64 мс без.
- SwiftShader (CPU, как в smoke): печать ~120–130 мс на кадр. Телефон не мерили.

## Известные проблемы
- Пятна пропусков стоят на экране неподвижно (по месту экрана, не по миру); сид подобран так, чтобы не попадать на машину.
- Ближняя дорога шире экрана: обочины видны только вдали; полосы асфальта — большие плоские куски (теперь с сухой краской).
- В пресете 2 дымка жёлтым почти сливает основания домов с небом — так задумано, но силуэты читаются хуже.
- Дым — ступенчатые жёлтые блоки; спидометр — DOM, не печатается.
