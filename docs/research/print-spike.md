# Спайк «печать» (`?print=1`) — одноразовый

Что сделано: обычный псевдо-3D кадр рисуется в `WebGLRenderTarget` 360×640 (nearest, RGBA, очистка альфой 0 = «ничего не нарисовано» = небо), затем один полноэкранный квад `ShaderMaterial` (`src/render/printPass.ts`) печатает его на холст 360×640 × `scale` (по умолчанию 1080×1920, CSS не меняется). Числа — `src/data/print.json`, перекраска заглушек — `src/data/palette.print.json`, слайдеры — группа «Печать» в dev-панели (`src/data/tunablesPrint.json`). Без флага путь и картинка прежние (все 10 эталонов `npm run shot` — 0.0000%).

Порядок в шейдере: поле бумаги с рваным краем → контур (key) по разнице соседних пикселей исходника + штриховка самых тёмных мест → иначе небо (если альфа 0: полосатая тоновая растяжка двух цветов растром + плоское солнце) или цветная форма (два ближайших цвета палитры, выбор одного по порогу растра) со сдвигом приводки → пропуски краски (бумага).

Цвет: при `?print=1` выключается `THREE.ColorManagement.enabled`, чтобы встроенный `MeshBasicMaterial` машины писал в RT те же sRGB-байты, что и наши шейдеры. Проверено чтением пикселей холста: в каждом кадре ≤ 16 цветов, все ровно из палитры.

## Слайдеры (группа «Печать»)
- Тип растра: 0 — точки на сетке, 1 — стохастика, 2 — Байер 4×4 по пикселю игры.
- Шаг / угол растра — размер ячейки точек (px экрана) и поворот сетки.
- Зерно стохастики — размер зерна для типа 1.
- Сдвиг цвета X / Y — приводка цветной формы относительно контура (px экрана).
- Порог контура — меньше = больше линий; толщина контура — px экрана.
- Шаг штриховки (0 — выкл.), порог яркости штриховки.
- Пропуски краски, пропуски у края — сколько бумаги просвечивает (пятнами, гуще у края).
- Поле бумаги, неровность края — ширина поля и рваность края картинки.
- Солнце: радиус (0 — нет), высота. Масштаб печати — множитель холста (1..4).
- Без слайдера, только в `print.json`: палитра, роли (бумага, ключ, цвета неба, солнце), растяжка неба (y0, y1, полосы), sunX, зерно/период пятен пропусков, длина волны рваного края.

## Замеры (2026-11-19, `node tools/spike/print-shots.mjs [--gpu]`)
- Ноутбук, AMD Radeon (D3D11), headless Chromium: живой цикл p50 16.7 / p99 16.8 мс (упор в vsync) с печатью и без; draw calls 4 против 3. Без vsync (рендер + синхронизация readPixels, сцена traffic): 2.46 мс с печатью против 0.71 мс без.
- SwiftShader (CPU, как в smoke): с печатью p50 133 / p99 200–317 мс (без печати 16.7 / 16.8), без vsync 120 мс против 5 мс — софт-растеризатор 2 Мпикс не тянет; это не телефон, на телефоне не мерили.

## Известные проблемы
- Тоновые переходы есть только там, где исходник не совпадает с палитрой (затенение машины и трафика, небо). Плоские заглушки остаются плоскими — растр почти не виден на дороге.
- Белая машина (кость) в тени уходит в голубые/розовые точки — читается, но выглядит голубой, а не костяной.
- Ближняя дорога шире экрана: обочины и поребрики видны только вдали; полосы асфальта (индиго/тёмно-фиолетовый) — огромные плоские куски с контурной линией между ними.
- Дым — ступенчатые жёлтые блоки (форма из старого спрайта).
- Солнце и растяжка неба не учитывают крен экрана (R27) и холмы: горизонт задан числом.
- Спидометр — DOM поверх холста, не печатается.
