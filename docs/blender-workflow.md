# Blender + Claude Code: стилизованные модели по фото

Как ставить Claude Code задачи в Blender через MCP-сервер Blender Lab и получать предсказуемый стиль.

## 1. Как это устроено

```
Claude Code ⇐ stdio ⇒ blender-mcp (Python, вне Blender) ⇐ TCP 127.0.0.1:9876 ⇒ аддон MCP в открытом Blender
```

- Сервер: `%USERPROFILE%\.blender-mcp\venv\Scripts\blender-mcp.exe`, пакет `blender-mcp` из `projects.blender.org/lab/blender_mcp`, закреплён на коммите `dbbf836` (2026-09-29).
- В Claude Code он подключён как `blender` в пользовательском конфиге (`~/.claude.json`), то есть виден во всех проектах. Переменная `BLENDER_PATH` указывает на Blender 5.3: она нужна инструментам `*_for_cli`, которые запускают Blender в фоне.
- Что умеет: выполнять Python в открытом Blender (`execute_blender_code`), делать скриншоты окна и отдельной области (`get_screenshot_of_area_as_image`), рендерить (`render_viewport_to_path`, `render_thumbnail_to_path`), описывать сцену и объекты, искать по документации API и мануала.
- Чего не умеет: «поднимать» меш из фотографии. Claude смотрит на фото глазами и строит модель кодом: примитивы, модификаторы, bmesh. Поэтому хорошо выходят стилизованные твёрдые формы (машины, пропсы, архитектура, low-poly), плохо — фотореализм и органика (лица, ткань, животные с мехом).

### Включение (один раз)
1. В Blender: Edit → Preferences → Get Extensions → найти **MCP** (репозиторий lab.blender.org уже подключён) → Install. Включить галочку.
2. В той же панели настроек аддона: включить **Auto-start**, нажать **Start**. Порт оставить 9876.
3. Перезапустить Claude Code (новый чат), чтобы он увидел сервер. Проверка: в чате спросить «покажи скриншот окна Blender».

Обновление сервера, когда выйдет новая версия:
```powershell
& "$env:USERPROFILE\.blender-mcp\venv\Scripts\python.exe" -m pip install -U "git+https://projects.blender.org/lab/blender_mcp.git#subdirectory=mcp"
```

### Безопасность
`execute_blender_code` выполняет любой Python внутри Blender: может писать файлы и удалять объекты. Перед сессией сохраняйте `.blend`; для экспериментов держите отдельный файл. Сервер слушает только `127.0.0.1`.

## 2. Какие фото присылать

Главное для модели — силуэт и пропорции, а не детали. Пропорции надёжнее всего передают ортогональные виды.

**Лучший набор (по убыванию пользы):**
1. **Чертёж (blueprint)** вид сбоку, спереди, сзади, сверху. Ищется как «<марка модель> blueprint». Один такой файл лучше десяти фото.
2. **Строгий профиль сбоку**: снято издалека, с зумом (длинный фокус убирает перспективу), камера на высоте середины кузова, машина целиком в кадре.
3. **Анфас и корма** так же: издалека, по центру, на уровне фар.
4. **Один ракурс 3/4** — для «характера» и того, как стыкуются плоскости. Пропорции по нему не снимать.
5. Крупно 1–2 узнаваемые детали, если они важны для стиля (фары, решётка, спойлер).

**Плохие фото:** широкоугольник вблизи (нос раздувается), сильный ракурс сверху или снизу, обрезанная машина, ночь, блики, пёстрый фон, тюнинг, если нужен стоковый вид.

**Числа сильно помогают.** Длина, ширина, высота, колёсная база, диаметр колеса (берутся из характеристик модели). С ними Claude строит в реальном масштабе, а фото нужны только для формы.

**Референс стиля — отдельной картинкой** и с подписью, что это стиль, а не форма: скриншот игры, своя раскадровка, арт. Иначе Claude смешает форму и стиль.

Называйте файлы по смыслу: `car_side.jpg`, `car_front.jpg`, `car_34.jpg`, `style_ref.png`. Удобно положить их в одну папку и дать путь; можно и вставить в чат (Ctrl+V или перетащить).

Для игры: если машина узнаётся как реальная марка, в коммерческом проекте лучше брать её как «вдохновение» (смешать черты двух-трёх машин, без логотипов и шильдиков). Это убирает вопросы с товарными знаками.

## 3. Как писать задачу

Хороший промпт отвечает на шесть вопросов: что строим, какие референсы за что отвечают, размеры, стиль числами, что упростить и что сохранить, как работаем (шаги и проверки).

### Шаблон стартового промпта
```
Задача: стилизованная модель <что> в открытом Blender, через MCP.

Референсы (форма): <путь>\car_side.jpg — профиль, главный по пропорциям;
car_front.jpg — анфас; car_34.jpg — только характер, пропорции по нему не бери.
Референс стиля: style_ref.png — только стиль, не форма.

Размеры: длина 4.2 м, ширина 1.75, высота 1.15, база 2.45, колесо Ø 0.62.
Масштаб в метрах, машина смотрит в −Y (вид спереди Blender), origin на земле по центру базы.

Стиль:
- low-poly, бюджет 300–600 треугольников на кузов, колёса по 8–12 сегментов;
- плоское затенение (flat), без текстур и без UV;
- 2–3 тона на объект: основной <hex>, тёмный <hex>, акцент <hex>; стекло <hex>;
- фаски только там, где они читаются в силуэте.

Сохранить обязательно: <2–3 черты, по которым узнаётся силуэт: клиновидный нос, короткая кабина, крыло на стойках>.
Упростить: зеркала, дворники, ручки, мелкие решётки — убрать или одной гранью.

Структура: коллекция CAR, объекты body, glass, wheel_FL/FR/RL/RR, lights; модификаторы не применять до моего ОК.

Как работаем:
1. Сначала блокинг только из крупных объёмов. Поставь фото фоном в ортогональные виды
   (Add → Image → Reference) и пришли скриншоты видов сбоку и спереди поверх референса.
2. Сам сравни силуэт с фото и перечисли расхождения, исправь, покажи снова. Потом жди моего ОК.
3. После ОК — детали, затем материалы. На каждом шаге скриншот.
4. В конце: сохрани в <путь>\car_v1.blend и экспортируй <путь>\car_v1.glb, сообщи число треугольников.
```

Пункт про пошаговую работу — самый важный. Если разрешить сделать всё за один заход, Claude налепит деталей на кривые пропорции, и исправлять придётся всё сразу.

### Промпты для итераций
Говорите о том, что видно в силуэте, лучше с числами и ссылкой на вид:
- «Сбоку: крыша на ~8 см выше, чем на фото, лобовое наклонить сильнее, примерно 25° к горизонту».
- «Задний свес короче на треть; колёса крупнее, верх колеса вровень с линией порога на фото».
- «Слишком много граней на капоте, оставь две плоскости и одно ребро».
- «Стоп, верни прошлый вариант кабины, остальное оставь» (Ctrl+Z в Blender тоже работает).
- «Наложи фото профиля полупрозрачно поверх вида сбоку и пришли крупный скриншот носа».

Если пошло совсем не туда, лучше начать заново с уточнённым промптом, чем чинить десятью правками.

## 4. Рецепты стилизации

Стиль надёжнее задавать параметрами, чем прилагательными. «Мультяшно» Claude поймёт по-своему; «3 тона, обводка 2 px, без отражений» — однозначно.

| Стиль | Что написать в промпте |
| --- | --- |
| Плоские заливки (Killer7-подобно) | flat shading, 2–3 тона на объект из палитры hex, без текстур; материал Emission или Workbench Flat, чтобы цвет не зависел от света; тени — отдельным тёмным тоном, не светом |
| Low-poly / PS1 | бюджет N треугольников, грубые фаски, текстура не больше 64×64 с nearest-фильтром либо vertex colors |
| Toon / cel | Shader to RGB → Color Ramp (Constant) на 2–3 ступени; обводка — Solidify с перевёрнутыми нормалями, толщина 0.01–0.02 м, или Line Art |
| Глина / игрушка | скруглённые формы (Bevel с 2–3 сегментами, Subdivision 1), один матовый цвет, мягкий свет |
| Чертёжный / техно | белые грани, тёмные рёбра (Freestyle или Wireframe), ортогональная камера |

Приёмы, которые почти всегда улучшают стилизацию:
- Утрировать узнаваемые черты на 10–20 % (ниже нос, шире колёса) и убирать всё, что не видно в силуэте с игровой дистанции.
- Проверять по маленькому чёрно-белому рендеру размером с игровой кадр. Если не читается там, детали не помогут.
- Палитру давать hex-кодами, а не словами.

## 5. Для Vermis Race

Игра остаётся на спрайтах (ADR 0003), поэтому модель машины здесь — источник для запекания кадров поворота, а не ассет для three.js. Стиль — из `docs/art-bible.md`: плоские заливки, 2–3 тона на объект, цвета из палитры (игрок `#cfd0d6`, соперники `#b4ff39` / `#ff3df0` / `#39e6ff`, трафик `#6f7480`). Готовые числа текущей заглушки — в `src/data/car3d.json` (клин 80-х, ~270 треугольников); их можно дать Claude как стартовые пропорции.

Добавка к шаблону промпта:
```
Это источник для пиксельных спрайтов 360×640, машина на экране ~86×51 px.
Важен только силуэт и крупные пятна цвета: деталей мельче 1/40 длины не делать.
Цвета строго из палитры (см. выше), освещение не влияет на цвет (Emission/Flat);
верх/перед/бок/зад/низ — оттенки ×1 / 0.9 / 0.76 / 0.62 / 0.35 от базового цвета, как в car3d.json.
```

Сам конвейер запекания (камера, число кадров поворота, разрешение, без сглаживания) — отдельный срез. Сначала переписываем R45 в брифе, потом делаем.
